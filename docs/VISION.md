# VISION.md — Mission & Vision

## Mission

Give Danish schools their time back.

Skoleoverblikket replaces the pile of spreadsheets, paper, and disconnected tools a small school runs on with one dead-simple system — so staff spend their time teaching, not doing admin.

## North star: save time

Time is the metric everything else serves.

- **Save time** → Hanne builds a term's schema in an afternoon instead of a week fighting Excel; Thomas finds his schedule in seconds instead of asking around.
- **Save money** follows from time saved: less staff time on admin is the real cost, subscription price is secondary — affordability is table stakes, not the pitch.
- **Raise school quality** is the long chain: less admin time → more time for teaching prep and student contact → better teaching. We don't claim to improve teaching directly. We claim to stop stealing time from it.

When a feature decision has to trade off simplicity against completeness, time saved for the actual user in front of the screen wins. See [PERSONAS.md](PERSONAS.md) — Hanne, Thomas, Birgitte, Mikkel are not edge cases, they're who every screen is built for.

## Why the product is broad but the scope is narrow

Skoleoverblikket covers schema planning, SFO, ugeplan, vikardækning, parent communication, fravær, ferieindmelding, filarkiv, bestyrelse, and compliance publishing — because a school's admin burden is spread across all of these, and forcing staff to sync data between separate tools recreates the exact time-waste we exist to remove.

## Why simplicity is non-negotiable

A feature only whoever built it can operate isn't saving anyone time — it's moving the time cost onto someone learning software instead of doing admin. Every feature must survive first contact with Hanne, unaided. That constraint is the product's real moat: cheaper *and* simpler than the alternatives, not cheaper *despite* being more complex.

## Who this document is for

- **Agents**: use this as the filter when a request is ambiguous or when scope is tempting to expand — does this save real time for a real user, without adding operating cost for Hanne?
- **New contributors**: this is why the product looks the way it does before you read a line of code.
